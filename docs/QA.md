# Verification evidence

## Automated behavior — 21 tests
`npm run typecheck`, `npm test`, and `npm run build` pass on Node 24. The suite exercises the exported simulation tick and storage seam: continuous movement/facing and jump landing; crouch locking; body/wall collisions; held-button edge behavior; recovery commitment; single aerial attack; hit range and single-hit active windows; high/low guarding; sweeps/knockdown and illegal actions while down; airborne overheads before landing; close throws/guard bypass; ordered/mirrored/expired/consumed quarter-circles; stability regeneration, stun and mash recovery; simultaneous trades; knockout/reset/first-to-two/rematch; timeout/draw; tactical AI approach/guard/reaction delay and full match; valid/corrupt/unavailable namespaced storage. Regression assertions verify active mid blocking rather than a collision miss and crouch posture throughout low-attack recovery.

## Native Mac Chrome — production preview
Performed through the connected Mac browser with native keypresses and clicks, against the production build at `http://127.0.0.1:5223`. No page state injection, synthetic DOM events, accelerated time, state-editing win shortcuts or test-mode changes were used. The visible canvas accessibility label reports live integrity/stability, stance and facing for inspection.

Observed:
- Engage starts a first-to-two match with a ready interval. Holding left/right changes position continuously. A clean neutral ↑ input visibly raises Kestrel above the floor; accessibility reports `airborne`, at 100 integrity.
- Down+K at round start reports `YOU / SWEEP` and `crouch`; screenshot shows crouched posture maintained during the move.
- J and K were used in exchanges. A sustained sequence of approach, crouching kicks, jab, retreat and low guard produced player integrity 100 versus opponent 89, confirming an ordinary player attack landed.
- Down+Left held against CPU pressure yielded visible `GUARD` status and player `block` state. CPU movement, jumps, crouching attacks, throws and lunging specials were visible. Wrong or late defense caused impacts and knockdowns; recovery returned to neutral.
- Performed actual Down (65ms), Down+Right (65ms), Right+J (65ms) after entering combat. Native screenshot showed the extended glowing strike and **YOU / MOTION VERIFIED / ARC DRIVE**. This label is player-specific; CPU specials cannot set it.
- Played through a complete match ending **BASALT WINS THE MATCH · 0–2 · Record saved locally**, with round markers/result/rematch button visible. Clicked Rematch and observed fresh 100/100 health and round one. Several additional matches/exchanges were played during QA.
- Reload showed the accumulated record retained (00–01 initially, then 00–04 after subsequent matches); combat itself restarted at the entry screen. Existing unrelated browser storage was not cleared or enumerated.
- Escape pauses and visible resume control works. The deliverable tab is left on a fresh entry screen.

## Limits
Native play verified a completed loss, not a human win. Win/match branching and stability-depletion mash recovery are simulation-tested; no native claim of winning or mashing out of a fully depleted stun bar. Left-facing motion recognition is simulation-tested; the native special was right-facing. No gamepad/mobile, multiplayer, broad cross-browser, audio-output recording or performance benchmark coverage. Audio is generated by Web Audio after user interaction; mute UI exists, but listening quality was not audited. Screenshots were inspected in the native tool session; no private browser/session images are included in the public repository.

## Preview isolation
Before startup, existing listeners were inspected and 5223 was free; ports through 5222 were avoided. Production Vite preview runs detached, bound to 127.0.0.1:5223. No prior server was stopped, sibling project edited, save cleared, security setting changed, or public website deployed. The preview uses `dist/` from the passing final build. Loopback server lifetime was verified separately from the launch process.
